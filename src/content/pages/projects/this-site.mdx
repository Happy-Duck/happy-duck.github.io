## Who built it

I did not write this site's code. Claude, Anthropic's AI model, did: the design, every line of the code, and the text on this page. My part is deciding what the site should be, trying what comes back, and saying what I do not like. There has been a lot of that last one.

I treat the site as a running experiment. When a notably more capable model comes out, I hand it the whole project and ask for an overhaul, mostly to find out what it can do with something it has to read, understand, and extend instead of starting clean. The commit history records which model made each change: every commit a model made ends with a line naming it, and the repository is public (linked at the top of this page).

## Scroll is depth

There is one number behind the whole site: how far down the page you are, from 0 at the surface to 1 at the floor. The color of the water, which animals are out, how dark it is, and what the depth gauge reads are all worked out from it.

<Note title="Why not a straight line">
Each zone gets a share of the page that suits what is in it. The top 200 metres hold the name and the first jobs, so they get a fifth of the scroll.
</Note>

The gauge does not simply multiply that number by 6,000. Real ocean zones are very uneven (the sunlit zone is 200 metres deep, the midnight zone 3,000), and the page is paced for reading, so the conversion runs zone by zone.

<CodeTour steps={[

```js
export function metersAt(depth) {
  const d = Math.max(0, Math.min(1, depth))
  const zone = getZone(d)
  const t = (d - zone.min) / (zone.max - zone.min)
  return zone.meterMin + t * (zone.meterMax - zone.meterMin)
}
```

## One clock

Every animal, particle, and bubble is moved by the same loop, once a frame. Early on, the fish swam twice as fast on a 120 Hz monitor as on a 60 Hz one, and slowed down whenever scrolling made the page stutter, because each frame moved them a fixed amount.

The fix is to measure how long the last frame really took and scale every movement by it.

<CodeTour steps={[

```js
const frameMs = lastNowRef.current > 0 ? now - lastNowRef.current : 1000 / 60
const dt = Math.min(2.5, Math.max(0.25, frameMs / (1000 / 60)))

subscribers.current.forEach(fn => fn(depth, dt))

// in a subscriber
const drag = Math.pow(DRAG, dt)
vx[i] = (vx[i] + ax * dt) * drag
```

## The water

Three parts of the scene are drawn on the graphics card.

- **Light from the surface.** Slanted shafts in the top few hundred metres, written as a WebGL2 shader at half resolution. It runs in a worker, so drawing it never holds up scrolling.
- **The fish school.** About 380 anchovies between roughly 40 and 400 metres, steered by a WebGPU compute shader and drawn from a real photo. Without WebGPU the school is simply absent and the other animals carry the scene.
- **Marine snow.** The drifting specks in deep water, with their motion worked out in the vertex shader. They brighten inside the beam of the light that follows the cursor.

<Callout title="Something that was built and thrown away">
The first version of the surface light was a web of bright caustic lines. That is what light looks like on the sea bed seen from above. This site is a side view of the water, so it was replaced with shafts.
</Callout>

## Pages over the dive

A page like this one does not replace the dive. It is laid on top, and the dive stays where it was. Closing the page puts you back at the same depth, with nothing reloaded. On a screen too narrow to show water beside the page, the dive is paused until you come back.

## What went wrong along the way

- **Fish at double speed.** The frame-rate problem above. It only showed on a fast monitor, and only when the page was not stuttering.
- **A white rectangle where the light should be.** Releasing the graphics context on cleanup left a dead one behind during development, which painted solid white. The context is now kept.
- **Ripples, twice.** A ripple effect on the surface was built two different ways and removed both times. The first was the wrong physics for a side view. The second was right and still not worth keeping.
